# Browser integration review

Use only a disposable WordPress single-site fixture. This suite changes theme/login settings, installs no external service, switches themes/plugins, creates an editor fixture and creates a fictitious cash-on-delivery order. Disable outgoing mail and all real payment methods first. It expects the bundled eight-product demo, Iranian classic checkout, guest checkout and COD, the parent and child themes, Navid Core, and an alternative default theme.

Install Node dependencies with `npm install`, then `npx playwright install chromium`. Set `NAVID_TEST_URL`, `NAVID_TEST_USER`, `NAVID_TEST_PASSWORD`, and optionally `NAVID_CHROME_PATH`. Defaults are localhost:9400 and the published demo credentials. Before running, copy `fixture.php` into the disposable site’s `wp-content/mu-plugins/navid-test-tools.php`. It provides an administrator-only, nonce-protected action that toggles a test option; the fixture reads it before regular plugins and defines the actual emergency constant. This avoids file synchronization races between PHP-WASM workers. It does not test editing a real host’s wp-config.php. Never install this test fixture on a live site. `NAVID_TEST_RESULTS` selects the result folder. Run `npm test`. The editor fixture stays in the test database; optional routing and autoplay are disabled in cleanup.

The recorded environment uses WordPress Playground CLI 3.1.58, PHP-WASM 8.3.33, WordPress 7.1.3, WooCommerce 11.2.1, Chrome Headless Shell 155.0.8059.84 and Playwright 1.62.1. Final reports are in `../reports/0.4.0`. Runtime tools are development dependencies and are not bundled in the installable theme. The optional `navid_test_env` query only has meaning in the local host fixture; it is not a theme endpoint.
